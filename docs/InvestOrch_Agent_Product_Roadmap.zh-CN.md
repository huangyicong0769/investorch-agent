# InvestOrch Agent 产品路线图

[English](InvestOrch_Agent_Product_Roadmap.md)

## 目的

本文记录已完成的工作、已确认方向、待决策事项和候选主题。版本、排期与详细 API 另行决定。

路线图使用四种状态：

- **已完成**：已有代码或测试支持的功能。
- **已确认方向**：已经选择的产品方向，具体版本、顺序与实现仍待决定。
- **待决策事项**：在相关工作开始时解决的问题。
- **候选主题**：在真实使用提供触发条件时重新评估的想法。

## 产品目标

InvestOrch Agent 的目标是成为面向个人投资者的本地优先、human-in-the-loop 投资编排产品，长期覆盖：

```text
研究
  -> 策略开发
  -> 回测
  -> 组合决策
  -> 交易
  -> 持仓监控与复盘
```

0.1.0 是这一目标的早期预览。

## 0.1.0 已完成

0.1.0 已包含：

- Web 和 TUI 两个一级客户端，以及诊断用 plain console；
- 本地配置、Workspace、Journal、日志、Session 元数据和 artifact；
- 持久化 Session 生命周期、跨 Session 并发 Run、Steer/Queue、审批、压缩和用量展示；
- Workspace、命令执行、配置、MCP registry 和 Todo Tool；
- 带可复现元数据与 artifact 输出的 RQAlpha 日频股票回测；
- 用于现有覆盖层和只读 MCP 路径的可选 CNEquity 集成。

组合/账户访问、QMT Gateway、实盘交易、统一投资数据层和 Multi-Agent 编排属于后续工作。

## 已确认方向：组合与 QMT 执行

0.1.0 之后的首个已确认方向是组合工作流与 QMT 执行。

以下细节仍待决定：

- 内部交付顺序；
- 组合、账户、订单或执行 API；
- 真实交易授权模式；
- Gateway 协议或部署模型。

InvestOrch Core 以 macOS 和 Linux 环境为目标。未来通过运行在 Windows/QMT 环境中的 Gateway 连接 QMT，而不在核心中直接 import XtQuant。

## 已确认方向：统一投资数据

统一、可追溯的投资数据能力是服务研究与回测的长期方向。目前尚未确认 schema、来源模型、存储引擎、更新生命周期、时点政策或查询接口。

CNEquity 仍是可选后端。更广泛的依赖要等待上游行为足够稳定，核心数据接口保持后端中立。

## 已确认方向：Multi-Agent

Multi-Agent 是长期方向。目前未确认 Specialist 角色、路由模型、Handoff 拓扑或实施排期。只有真实职责证明拆分能降低复杂度后，才设计 Agent 边界。

## 已确认方向：Agent as MCP

未来将通过 MCP server 对外提供经过选择的 Agent 能力，让其他 MCP client 可以调用 InvestOrch Agent。对外能力范围、Session 模型、认证方式、传输方式和审批行为仍待决定。

## 待决策事项

以下问题在对应产品工作开始时解决：

- 真实交易采用逐次审批、批次授权还是限额自治；
- QMT Gateway 如何通信、认证、部署和恢复；
- 统一数据层拥有什么，以及如何表达来源与时间；
- 哪些职责（如果有）需要成为独立 Agent；
- Agent as MCP 对外提供哪些能力，以及如何处理 Session、认证和审批；
- 已确认方向如何对应未来版本或里程碑。

## 候选主题

以下主题在出现真实使用触发条件时评估：

- **结构化文件与表格**：当重复出现的投资工作流无法由 Workspace 和现有命令执行可靠完成时再评估。
- **确定性分析辅助能力**：当重复计算需要稳定的领域接口，而不是普通 Python 或成熟库时再评估。
- **丰富 artifact**：当用户反复需要受治理的 spreadsheet、chart、PDF 或 report 输出，且普通文件不足时再评估。
- **外部研究集成**：当当前 MCP 集成无法满足具体工作流时再评估。

## 维护规则

仅在以下情况更新本文：

1. 代码和测试改变已完成的功能；
2. 产品方向或待决策事项得到确认；
3. 真实使用为候选主题提供触发条件。
