# InvestOrch Agent 0.2.0 — 发布准备

[English](0.2.0.md)

**状态：未发布。** 本文说明 `release/0.2.0-preparation` 上的 0.2.0 候选版本。软件包验证、实机验收与人工 review 完成后，创建 `v0.2.0` 和发布 GitHub Release 仍是独立动作。

InvestOrch Agent 是面向个人投资者的本地优先、human-in-the-loop 投资编排 Agent。0.2.0 在 0.1.0 的 Web、TUI 和 plain console 基础上新增 Portfolio 会计、受管 Skills、图片对话与配置/恢复工作流。

## 相比 0.1.0 的变化

### Portfolio 会计

- 使用独立 SQLite 数据库保存 Portfolio 元数据与追加式 Ledger，以精确十进制数、移动加权平均成本和显式未知成本重建持仓与逻辑现金。
- 经审批的 Agent Tool 创建/归档/恢复 Portfolio、初始化期初状态、记录实际成交/资金流/收入、追加纠错，以及在 Portfolio 之间原子转移。
- 只读 Web 页面浏览 Portfolio；New Portfolio 和 Ask Agent 进入 Agent 工作流，成功的结构化 Portfolio 交互将对象关联到 Session。归档、恢复和 Fork 保留身份关系。
- 在固定轮次边界审查完整有效用户指令历史，授权上下文可压缩，失败转人工审批。持久化前须确认重要交易事实与费用的依据。

每个 Portfolio 使用单一记账币种。Ledger 记录不代表订单、目标或券商余额。本版本不计算市值、NAV、收益率或业绩。

### 受管 Skills 与图片

- 提供六个内置 Skill：`skill-creator`、`skill-installer`、`investorch-configuration`、`investorch-portfolio`、`rqalpha-strategy` 和 `qmt-strategy`。
- 启动发现 Skill 元数据，按需加载内容。外部/新建候选先进行独立安全审查，再沿用正常审批；blocked 候选禁止安装，warning 须人工批准。
- Web 可查看 Skill 并打开 Create/Install/Edit/Fork Session。显式 `investorch --update` 使用包内容替换受管内置 Skill，保留 enabled 状态和自定义 Skill。内置定制应 Fork，catalog 修改后须重启。
- Web 对话通过文件选择、粘贴或拖放发送 JPEG、PNG、GIF、WebP；图片保存在历史中，`explore` 可读取 Workspace 图片，外部图片经点击才加载。

QMT Skill 为人工审查和大 QMT 部署生成 Artifact，不提交订单。

### Setup、配置与恢复

- Python Schema 统一定义默认值、类型、校验和生命周期元数据。Local TOML 保存用户覆盖和凭据；配置更新/重置经过原子校验与持久化。
- 新实例先打开 Web Setup，再启动 Agent；显式填写 Responses 兼容 Endpoint、模型名称和凭据，不预选 Provider。可选连接测试会发送真实模型请求。
- Settings 管理持久偏好，未来 Run 临时覆盖保持进程级。需要重启的变化，包括替换凭据，在下次启动后生效。
- MCP Integrations 通过 `streamable_http` 管理独立的 `mcp.toml`。未修改的隐藏凭据保持原值；更新须重启，清空显式 timeout 恢复应用默认值。
- System Status、`doctor` 和 `upgrade check` 离线检查本地状态，不调用模型、不连接 MCP、不迁移、不更新 Skill。配置、存储或已启用 Skill 阻止启动时，Web 保持修复指引可用。
- 离线备份创建/验证保留 SQLite 快照和 Workspace 历史。默认排除原始凭据配置，所有归档均未加密；恢复是向空 Root 手工操作。

## 安装候选版本

需要 Python 3.12 或更高版本与 [uv](https://docs.astral.sh/uv/)。发布前使用准备分支：

```sh
git clone --branch release/0.2.0-preparation https://github.com/huangyicong0769/investorch-agent.git
cd investorch-agent
uv sync --locked
uv run --locked investorch web
```

打开 <http://127.0.0.1:1334> 完成 Setup。已有用户先按[升级说明](../Upgrade.zh-CN.md)操作，再使用新候选启动原 Root。

准备的发行文件为 `investorch-0.2.0-py3-none-any.whl`、`investorch-0.2.0.tar.gz` 与 `SHA256SUMS`。使用从选定候选 commit 构建并验证的 Artifact；正式发布后从 [GitHub Releases](https://github.com/huangyicong0769/investorch-agent/releases) 下载。先使用随包校验文件检查 wheel：

```sh
# macOS
grep 'investorch-0.2.0-py3-none-any.whl$' SHA256SUMS | shasum -a 256 -c -
# Linux
grep 'investorch-0.2.0-py3-none-any.whl$' SHA256SUMS | sha256sum -c -

uv tool install ./investorch-0.2.0-py3-none-any.whl
investorch web
```

可选 CNEquity 集成：源码使用 `uv sync --locked --extra cnequity`，已验证 wheel 使用 `uv tool install './investorch-0.2.0-py3-none-any.whl[cnequity]'`。CNEquity 保持固定为 0.7.3。

## 从 0.1.0 或更早源码升级

保留旧软件包，备份前停止全部写入者。0.1.0 不包含新的 Doctor/Backup CLI，因此先使用候选版本的离线命令，不必先替换旧安装。[升级说明](../Upgrade.zh-CN.md)提供候选预检、配置校验、备份和核对步骤。

0.2.0 不继承 0.1.0 随包 Provider 默认值。模型 Endpoint、模型名称和 Secret 引用必须显式填写。未知或非法 Local TOML 字段需修复；不提供自动 Local TOML 迁移。

Portfolio schema v1/v2 使用经备份的迁移路径；v3–v5 须先停止旧 `PREPARED`/`ACTIVE` deployment，再显式运行 `investorch migrate portfolio`；v6 直接复用。Dry-run 只读并拒绝 WAL 模式。应保留原文件并按 remediation 处理，而不是删除数据。

旧 `--sync` / `--sync-force` 参数已移除。先查看受管内置 Skill 差异，再执行会替换其内容的 `investorch --update`。自定义 Skill 和用户 Memory 保留。重启后核对 Session ID/历史、Portfolio ID/Ledger/投影、Skill enabled 状态和关键 Workspace 文件。

## 平台与安全边界

核心应用面向 macOS 和 Linux。Agent `exec_command` 目前**仅支持 macOS**。Linux ApplicationHost 能启动以及 CI 通过，不代表支持命令执行。当前支持声明不包含 Windows 原生应用验收。

Web 监听 loopback，限制本地 Host 与同源 JSON 写请求，没有经过认证的 LAN 模式。配置、历史和 Artifact 默认本地存储；已配置的 Provider 与 MCP server 接收调用内容。安装 Skill 不代表授权执行其脚本。

实盘交易、QMT Gateway、券商账户同步与对账、FX 会计、统一投资数据层和 Multi-Agent 编排属于后续工作。
