# InvestOrch Agent 0.3.0 — unreleased

[简体中文](0.3.0.zh-CN.md)

This document describes the 0.3.0 development line. It is not a release announcement; package versions and published installation instructions still identify 0.2.0.

## Session collaboration

Agents can discover Sessions with `list_sessions`, read their history with `read_session`, and send approved text or images with `send_message`. Messages enter the recipient's normal user-input path with sender provenance and ordinary approval rules. A receipt confirms submission, not completion; Queue state remains process-local.

`spawn_agent` creates an ordinary child Session with independent history and approvals. Children can spawn recursively, share the global Run limit and receive a one-time Portfolio association snapshot. Spawn inherits its parent's active model unless explicitly overridden. Delete/Clear checks the full descendant scope and rejects active work or independent Fork references.

## Model connections and ChatGPT

Configuration now separates reusable `models.<connection>` from the five `agents.<role>` defaults. Connections can use an OpenAI-compatible API key or official local ChatGPT authorization. ChatGPT uses account-specific model choices and on-demand credential refresh; login, logout and refresh apply without restarting the Host. Usage limits or missing plan access do not silently change accounts or switch to paid API usage.

Web Setup and Settings manage connections and Agent defaults separately. **Continue with ChatGPT** opens browser authorization; an eligible account must explicitly grant plan usage. ChatGPT-only setups need no API key. API keys and OAuth tokens remain private in Local TOML. Connections and Agent defaults require restart; an optional connection test makes a small real request. See [Configuration](../Configuration.md) for complete API and multi-account examples.

## Model selection per Session

The conversation header, TUI/plain `/model` and `/effort` edit the selected Session's next-Run Draft. The next accepted Run persists a frozen connection, actual model, effort and positive context window. An active Run keeps its selection. Queue resolves the latest Draft when promoted; Steer keeps the active model. Fork preserves persisted selections and copies uncommitted selections as Drafts. Unused Drafts disappear on process exit.

Preflight compaction checks whether continuation and new input fit the selected Run window before Main inference, even when post-answer automatic compaction is disabled. Failure or a still-oversized request blocks Main. Compaction preserves the complete Journal. Each new Run sends a copy of prior history without opaque reasoning or provider response-item IDs, retaining messages and function call links; stored originals remain intact. This applies to unchanged connections too, with possible cross-Run continuity or cache costs.

## Breaking upgrade

Old `models.<role>` TOML is incompatible. Convert endpoint/key fields into named connections, then move model name, effort and window into `agents.<role>` and add the connection reference. There is no automatic TOML migration or `config_version`. Existing Session SQLite metadata gains nullable model fields through normal initialization; legacy unbound Sessions use the new Main default on their next Run.

Before upgrading, stop every writer, preserve the prior environment and complete root, capture old effective role settings, convert a copy offline, then verify readiness and data. Rollback restores the complete pre-upgrade root and prior environment. Follow [Upgrade](../Upgrade.md) rather than starting the new code against an unconverted original root.

The managed `investorch-configuration` Skill becomes 1.2.0. Existing instances adopt it only through explicit `investorch --update`, followed by restart. Custom Skills, Memory and enable state retain their existing update semantics.

## Scope

Agent as MCP is cancelled for 0.3.0 and is no longer a confirmed future direction. Existing MCP client integrations continue. PyPI distribution, live trading, a QMT gateway and broker/account synchronization are outside this change. See [Product Roadmap](../InvestOrch_Agent_Product_Roadmap.md).
