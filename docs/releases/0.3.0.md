# InvestOrch Agent 0.3.0

[简体中文](0.3.0.zh-CN.md)

InvestOrch Agent 0.3.0 adds multi-agent orchestration, reusable model connections and ChatGPT authorization, per-Session model selection, continuous context management, and improved runtime diagnostics.

## Multi-Agent orchestration

0.3.0 brings together task delegation, recursive child Sessions, cross-Session communication, result inspection and Web task management. Agents can divide work, coordinate follow-ups and read child results for integration.

Agents can discover Sessions with `list_sessions`, read their history with `read_session`, and send approved text or images with `send_message`. Messages enter the recipient's normal user-input path with sender provenance and ordinary approval rules. A receipt confirms submission, not completion; Queue state remains process-local.

`spawn_agent` creates an ordinary child Session with independent history and approvals. Children can spawn recursively, share the global Run limit and receive a one-time Portfolio association snapshot. Spawn inherits its parent's active model unless explicitly overridden. Web shows parent/child relationships, live task status and navigation. Delete/Clear checks the full descendant scope and rejects active work or independent Fork references.

## Model connections and ChatGPT

Configuration now separates reusable `models.<connection>` from the five `agents.<role>` defaults. Connections can use an OpenAI-compatible API key or official local ChatGPT authorization. ChatGPT uses account-specific model choices and on-demand credential refresh; login, logout and refresh apply without restarting the Host. Usage limits or missing plan access do not silently change accounts or switch to paid API usage.

Web Setup and Settings manage connections and Agent defaults separately. **Continue with ChatGPT** opens browser authorization; an eligible account must explicitly grant plan usage. ChatGPT-only setups need no API key. API keys and OAuth tokens remain private in Local TOML. Connections and Agent defaults require restart; an optional connection test makes a small real request. See [Configuration](../Configuration.md) for complete API and multi-account examples.

## Model selection per Session

The composer’s model/effort control, TUI/plain `/model` and `/effort` edit the selected Session's next-Run Draft. The next accepted Run persists a frozen connection, actual model, effort and positive context window. An active Run keeps its selection. Queue resolves the latest Draft when promoted; Steer keeps the active model. Fork preserves persisted selections and copies uncommitted selections as Drafts. Unused Drafts disappear on process exit.

Preflight compaction checks whether continuation and new input fit the selected Run window before Main inference, even when automatic compaction is disabled. With automatic compaction enabled, context is also checked between tool turns. Failure or a still-oversized request blocks Main. Compaction preserves the complete Journal, outstanding work, and the tool call/result links needed to continue. Each new Run sends a copy of prior history without opaque reasoning or provider response-item IDs; stored originals remain intact. This applies to unchanged connections too, with possible cross-Run continuity or cache costs.

## Runtime feedback and Web workflows

- Show Main and auxiliary usage as requests complete, including consumed preflight usage when later work fails or is cancelled. Display provider reasoning summaries in activity titles where available.
- Persist actionable, redacted Run failures in conversation history. Approval rejection feedback reaches the Main Agent so it can correct its next action.
- Preserve in-progress approvals, drafts and navigation across refresh, resize and reconnect. Keep orphaned background processes visible in System Status, and distinguish diagnosed problems from unchecked connections.
- Isolate failed MCP connections from the Agent Run and retain safe initialization causes for diagnosis.

## Strategy workflows and dependencies

Built-in Skills now spell out specialist toolchains, artifact handoffs and verification. RQAlpha research uses the native inspection/backtest tools, with typed per-run execution parameters, serialized engine execution, native logs and actionable engine rejection feedback. Portfolio writes require Ledger readback; QMT artifacts remain subject to human review and deployment.

Refresh Python, Web and build dependencies and lockfiles, including OpenAI Agents SDK 0.24.0, FastAPI 0.161.1, RQAlpha 6.4.2 and uv_build 0.13.5. Release packages do not install CNEquity; its integration code is retained. Source installations use the committed lockfiles; regenerate the production Web bundle before packaging frontend changes.

## Installation and distribution

0.3.0 provides wheel and source distributions through PyPI, alongside GitHub artifacts and SHA-256 checksums. Installation from source or a verified release wheel is described in the [README](../../README.md#installation).

Install with uv:

```sh
uv tool install --python 3.12 investorch==0.3.0
```

Python 3.12–3.14 (`>=3.12,<3.15`) remains required.

Maintainers can follow the [release procedure](../Publishing.md) for GitHub and PyPI publication.

## Breaking upgrade

Old `models.<role>` TOML is incompatible. Convert endpoint/key fields into named connections, then move model name, effort and window into `agents.<role>` and add the connection reference. There is no automatic TOML migration or `config_version`. Existing Session SQLite metadata gains nullable model fields through normal initialization; legacy unbound Sessions use the new Main default on their next Run.

Before upgrading, stop every writer, preserve the prior environment and complete root, capture old effective role settings, convert a copy offline, then verify readiness and data. Rollback restores the complete pre-upgrade root and prior environment. Follow [Upgrade](../Upgrade.md) rather than starting the new code against an unconverted original root.

Managed built-in Skills include updated configuration and strategy guidance. Existing instances adopt package copies only through explicit `investorch --update`, followed by restart. Custom Skills, Memory and enable state retain their existing update semantics.

## Scope

Agent as MCP is cancelled for 0.3.0 and is no longer a confirmed future direction. Existing MCP client integrations continue. Live trading, a QMT gateway and broker/account synchronization remain outside this release. See [Product Roadmap](../InvestOrch_Agent_Product_Roadmap.md).
