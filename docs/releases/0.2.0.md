# InvestOrch Agent 0.2.0 — release preparation

[简体中文](0.2.0.zh-CN.md)

**Status: unreleased.** These notes describe the 0.2.0 candidate on `release/0.2.0-preparation`. Publishing a GitHub Release and creating `v0.2.0` remain separate actions after qualification and human review.

InvestOrch Agent is a local-first, human-in-the-loop investment orchestration Agent for an individual investor. 0.2.0 adds Portfolio accounting, managed Skills, image conversations, and configuration/recovery workflows to the Web, TUI and plain-console clients introduced in 0.1.0.

## Changes from 0.1.0

### Portfolio accounting

- Persist Portfolio metadata and an append-only Ledger in a separate SQLite database. Rebuild holdings and logical cash with exact-decimal arithmetic, moving weighted-average cost and explicit unknown cost.
- Use approved Agent Tools to create/archive/restore Portfolios, initialize opening balances, record actual trades, cash flows and income, append corrections, and perform atomic transfers between Portfolios.
- Browse read-only Web Portfolio pages. New Portfolio and Ask Agent start Agent workflows; successful structured Portfolio interactions relate the object to its Session. Archive, restore and fork preserve these identities.
- Review the complete active user instruction history at a frozen turn boundary, with bounded authorization compaction and manual fallback. Material transaction facts and fees must be grounded before persistence.

Each Portfolio has one base currency. Ledger facts are not orders, targets or broker balances. This release does not calculate market value, NAV, returns or performance.

### Managed Skills and images

- Install six built-ins: `skill-creator`, `skill-installer`, `investorch-configuration`, `investorch-portfolio`, `rqalpha-strategy` and `qmt-strategy`.
- Discover Skill metadata at startup and load content on demand. Review external/created candidates independently before normal approval; blocked candidates cannot be installed, and warnings require manual approval.
- Inspect Skills in Web and open Create/Install/Edit/Fork Sessions. Explicit `investorch --update` replaces managed built-ins with package content and preserves enabled state and custom Skills. Fork built-ins for customization; restart after catalog changes.
- Send JPEG, PNG, GIF and WebP in Web conversations by file selection, paste or drop; retain images in history and read Workspace images through `explore`. External images load only after a click.

The QMT Skill authors artifacts for human review and deployment in Big QMT. It does not submit orders.

### Setup, configuration and recovery

- Python Schema owns defaults, types, validation and lifecycle metadata. Local TOML holds user overrides and secrets; configuration updates/reset validate and persist atomically.
- Fresh Web starts offer Setup before Agent startup. Configure Responses-compatible endpoints, model names and credentials explicitly, with no preselected provider. An optional connection test makes a real model request.
- Settings manages persistent preferences; future-Run temporary overrides remain process-local. Restart-required changes, including replaced credentials, take effect on the next application start.
- MCP Integrations manages the separate `mcp.toml` registry using `streamable_http`. Hidden credentials are preserved when unchanged; updates require restart, and clearing an explicit timeout restores the application default.
- System Status, `doctor` and `upgrade check` inspect local state without model calls, MCP connections, migration or Skill updates. Web preserves repair guidance when configuration, storage or enabled Skills prevent startup.
- Offline backup create/verify preserves SQLite snapshots and Workspace history. Default archives exclude raw credential configuration; every archive is unencrypted. Recovery is a manual operation into an empty root.

## Install a candidate

Requires Python 3.12 or newer and [uv](https://docs.astral.sh/uv/). Use the preparation branch before publication:

```sh
git clone --branch release/0.2.0-preparation https://github.com/huangyicong0769/investorch-agent.git
cd investorch-agent
uv sync --locked
uv run --locked investorch web
```

Open <http://127.0.0.1:1334> and complete Setup. Existing users should follow [Upgrade](../Upgrade.md) before starting the new candidate against their original root.

The prepared distribution names are `investorch-0.2.0-py3-none-any.whl`, `investorch-0.2.0.tar.gz` and `SHA256SUMS`. Use the artifacts built and qualified from the selected candidate commit. Once published, download them from [GitHub Releases](https://github.com/huangyicong0769/investorch-agent/releases). Verify the wheel with its checksum file:

```sh
# macOS
grep 'investorch-0.2.0-py3-none-any.whl$' SHA256SUMS | shasum -a 256 -c -
# Linux
grep 'investorch-0.2.0-py3-none-any.whl$' SHA256SUMS | sha256sum -c -

uv tool install ./investorch-0.2.0-py3-none-any.whl
investorch web
```

For the optional CNEquity integration, use `uv sync --locked --extra cnequity` in source, or `uv tool install './investorch-0.2.0-py3-none-any.whl[cnequity]'` with the qualified wheel. CNEquity remains pinned to 0.7.3.

## Upgrade from 0.1.0 or an earlier source checkout

Keep the prior package and stop every writer before backup. 0.1.0 does not include the new Doctor/Backup CLI, so use the candidate's offline commands without first replacing the old installation. [Upgrade](../Upgrade.md) explains candidate preflight, configuration validation, backup and verification.

0.2.0 does not inherit the packaged provider defaults from 0.1.0. Model endpoints, model names and secret references must be explicit. Invalid or unknown Local TOML fields require repair; automatic Local TOML migration is not provided.

Portfolio schema v1/v2 upgrades through the backed-up migration path; v3–v5 requires explicit `investorch migrate portfolio` after stopping legacy `PREPARED`/`ACTIVE` deployments. Schema v6 is reused. Dry-run is read-only and rejects WAL mode; keep originals and follow the remediation rather than deleting data.

The old `--sync`/`--sync-force` flags are removed. Review managed built-in differences before `investorch --update`, which replaces their content. Custom Skills and user Memory are preserved. Restart and check Session IDs/history, Portfolio IDs/Ledger/projections, Skill enabled state, and critical Workspace files.

## Platform and safety boundaries

The core targets macOS and Linux. Agent `exec_command` currently supports **macOS only**. Linux ApplicationHost startup and CI checks do not establish shell-command support. Windows-native application qualification is outside the current support claim.

Web binds to loopback, enforces local Host and same-origin JSON writes, and has no authenticated LAN mode. Configuration, histories and artifacts stay local by default; configured providers and MCP servers receive call content. Skill installation does not authorize execution of its scripts.

Live trading, a QMT gateway, broker/account synchronization and reconciliation, FX accounting, a unified investment data layer and Multi-Agent orchestration remain future work.

## Publication requirements

Before publishing, qualify the final candidate commit and its wheel/source distribution, complete dependency and license checks, and retain the checksum manifest. Record real application results for fresh Setup, existing-root upgrade/recovery, Web/TUI/plain, provider-backed Agent and approval flows, Portfolio facts/corrections/transfers, Skills, images, MCP, backups, and RQAlpha/CNEquity paths. Distinguish actual provider/server/data results from isolated substitutes; identify any unavailable or failing coverage. The candidate remains unaccepted while a required release check is unresolved.

The release review must use the final artifacts and evidence.
